## 1. 开发目标

实现基于 TypeScript 的 SVG 命令行编辑器，支持基本图形编辑、嵌套分组、撤销重做及 SVG 文件读写。采用面向对象设计，使用 Command 管理编辑操作，使用 Composite 统一处理叶子图形和容器。

本阶段支持 rect、circle、ellipse、line、text、g 六种类型，覆盖需求中的文档命令、编辑命令、显示命令和历史命令。box、动态插件、图形界面及完整 SVG 标准兼容不在本阶段范围内。

交付内容包括源码、依赖配置、自动化测试、示例脚本、SVG 样例和开发文档。Git 按功能阶段记录开发过程，最终交付提交使用 `final` 标签。

## 2. 技术方案

### 2.1 模块划分

| 模块 | 职责 |
|---|---|
| domain | 图形行为、画布、树结构、唯一 id、属性校验 |
| application | 编辑命令、文档会话、历史管理、查询及反馈 |
| cli | 输入分词、REPL、提示符与错误输出 |
| adapters | XML 编解码、文件读写、终端展示 |
| main.ts | 组装依赖、启动程序 |

依赖由外层指向内层：application 依赖 domain；cli 依赖 application；adapters 实现 application 中的端口。domain 不依赖终端、Node IO 或 XML 库。目录结构、组件图和模式实现见 [开发文档](README.md)。

### 2.2 实施顺序

```text
工程配置 → 领域模型 → 创建与查询 → 完整编辑与历史 → SVG 读写 → 集成验收 → 发布
```

领域树结构和历史恢复是主要依赖链。XML 库验证与领域模型开发穿插进行；测试和文档随功能阶段更新。

编辑命令在文档副本上执行，成功后替换当前文档；失败时丢弃副本。undo/redo 使用编辑前后的完整快照。SVG 解析和文件访问通过端口隔离，便于独立测试命令与文件失败行为。

## 4. 关键实现约定

### 4.1 图形与树结构

所有图形具有唯一且大小写敏感的 id，根画布不参与图形 id 寻址。一个节点只能有一个父容器，不允许环和重复引用。id 索引与树同步维护，删除容器时删除整棵子树。

`group` 按原文档顺序收编节点，新组位于原父容器的最近公共祖先中，占最早受影响的直接子分支位置。`addto` 将节点追加到目标容器末尾。跨父重组保留局部属性，样式继承和遮挡关系可能随父节点改变。

`ungroup` 将嵌套组的子节点按顺序提升到原组位置；根级组不可解散。`front` 对应 SVG 子列表末尾，`back` 对应开头。

### 4.2 数值与属性

坐标允许负数和浮点，画布尺寸为正，图形尺寸、半径及 stroke-width 非负。拒绝 NaN、Infinity 和非法数字后缀。

`scale` 以原点为中心缩放位置和尺寸，组递归处理后代；stroke-width 不随几何缩放改变。组的样式只写入自身属性，按 SVG 继承规则生效。set 仅接受公共样式、类型几何属性及文本内容。

### 4.3 历史与失败处理

成功的 init、read、save、canvas 尺寸修改清空历史并设置屏障，下一次成功编辑解除屏障。查询、注释和失败命令不影响历史。undo 后的新成功编辑清空 redo。

所有编辑在工作副本上完成。反馈生成、树约束及属性校验均通过后，才提交文档和历史。有效但无内容变化的编辑仍占一个历史单元。

### 4.4 文件与解析

首次 save 需要路径；成功的显式 save 和 read 更新默认路径，init 清除路径。保存使用同目录临时文件替换目标。

SVG 读入先收集全部显式 id，再为缺失 id 分配标签名加最小可用序号。支持六种元素、白名单属性及默认 viewBox。不支持的图形、transform、其他 viewBox、样式指令等明确报错。文本使用 XML 解析和转义处理，回车字符通过字符引用保存。

### 4.5 命令反馈

叶子移动报告目标坐标，容器移动报告增量；撤销报告恢复后的坐标、内容或归属。重做返回对应成功结果，不添加统一前缀。反馈测试直接提取需求文档中的会话，与每条命令的结果逐字比较。
